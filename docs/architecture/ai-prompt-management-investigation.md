## 1. Executive Summary

### Observed State of Enprive Today
Enprive already implements a functioning **hybrid AI pipeline** across Flutter UI (`lib/`), a deterministic Dart domain/evidence layer (`lib/domain/`), and a single native Android Kotlin bridge (`android/app/src/main/kotlin/com/example/enprive/MainActivity.kt`) over `MethodChannel('com.enprive/hybrid_ai')`. Contrary to early product briefs that envisioned Flutter `firebase_ai` plugins calling cloud endpoints directly from Dart:
1. **`pubspec.yaml` contains zero Firebase packages** (`firebase_core`, `firebase_ai`, `firebase_app_check`, and `firebase_remote_config` are completely absent).
2. **All generative AI calls live in native Android Kotlin** using `com.google.firebase:firebase-ai:18.2.0` and `com.google.firebase:firebase-ai-ondevice:16.0.0-beta08` inside `MainActivity.kt` (`createOnDeviceModel()` and `createModel()`), hardcoded against `"gemini-3.8-flash"` and `GenerativeBackend.googleAI()`, with `useLimitedUseAppCheckTokens = true`.
3. **Only two prompt instructions exist**, both concatenated as raw Kotlin string literals in `MainActivity.kt` (`L414-457`) without `systemInstruction` separation or server-side schemas.
4. **Deterministic verification works cleanly in Dart** (`EvidenceValidator` quote alignment + `PermissionComparator` local Android permission matching + `PiiRedactor` regex scrubbing + SQLite `ReceiptRepository`), cleanly decoupling model output from evidence truth.
5. **Two critical architectural gaps exist in current code vs. Enprive's product specification**:
   - **Silent Cloud Escalation Contradiction**: While `MainActivity.kt` (`L365`) blocks `ONLY_IN_CLOUD` without consent, and `lib/widgets/cloud_consent_sheet.dart` implements a full per-check consent bottom sheet, `ReviewCoordinator.runPolicyReview` (`L160-256`) and `askDeniAboutFinding` (`L441-465`) **silently flip `cloudConsent: true` with `InferenceMode.PREFER_ON_DEVICE`** whenever text is `>1,400 chars`/`>220 words` or Gemini Nano is unavailable—and `CloudConsentSheet` has **zero production callers**.
   - **Disconnected Features & Preferences**: `ExplanationDepth` (`simple`, `balanced`, `detailed`) is persisted and surfaced in Settings/Onboarding but never forwarded to prompts; dedicated document translation and multi-turn Deni chat are absent; iOS (`ios/Runner/AppDelegate.swift`) has zero AI/Firebase implementation; Firebase Remote Config is completely absent; and URL checking in `lib/main.dart` (`L1207-1239`) uses synthetic fixtures rather than fetching live URLs.

### Core Architectural Findings on Server Prompt Templates & Remote Config
1. **Firebase AI Logic Server Prompt Templates (`TemplateGenerativeModel`) are already bundled in Enprive's Kotlin dependency (`com.google.firebase:firebase-ai:18.2.0`)**, as confirmed directly in compiled SDK bytecode (`com.google.firebase.ai.TemplateGenerativeModel`, `TemplateChat`, `TemplateTool`). Adopting them in Kotlin avoids splitting Firebase initialization and App Check across Kotlin and Dart (`firebase_ai` `@experimental` on `pub.dev`).
2. **Server Prompt Templates are strictly cloud-only (Public Preview)** and **do not support** `ONLY_ON_DEVICE`, hybrid fallback (`PREFER_ON_DEVICE`), `LiveGenerativeModel` bidirectional audio, or output enum-list constraints.
3. **Global "Template-Only Mode" is incompatible with Enprive's hybrid `GenerativeModel` fallback**: Enabling project-wide Template-Only mode rejects all non-template `GenerativeModel` cloud requests (including `PREFER_ON_DEVICE` overflow fallbacks) with `403 Unauthorized`. Enprive must keep Template-Only mode **OFF** while any hybrid `GenerativeModel` cloud fallback or non-templated cloud path exists.
4. **Default AI Monitoring Logging Hazard**: Firebase AI Logic's default Cloud Logging/Trace monitoring captures full prompts and responses in Google Cloud Logging unless excluded via log sink filter (`resource.type="firebasevertexai.googleapis.com/Client"`) or disabled—requiring mitigation before routing sensitive parent/child-context prompts through cloud templates.
5. **Recommendation Summary**: **ADOPT WITH MODIFICATIONS** Server Prompt Templates **strictly for explicitly consented cloud-only tasks** (starting with a small proof of concept for finding explanation `enprive-finding-explanation-cloud-v1-0-0`, followed by Deni companion and split translation templates), **ONLY AFTER** fixing the silent cloud escalation bug and logging hazard. Keep local `ONLY_ON_DEVICE` Gemini Nano 4 prompts in versioned Kotlin/asset files, keep deterministic `EvidenceValidator` and `PermissionComparator` in local Dart, and integrate standalone Android `firebase-config` (without `firebase-analytics`) for safe allowlist-validated template pointers and a cloud-template kill-switch.

## 2. Existing AI Architecture Map

### Layer-by-Layer Map (Observed Codebase)

1. **Flutter Presentation & Localization Layer (`lib/screens/`, `lib/widgets/`, `lib/l10n/`)**
   - `EnpriveApp` / `HomeScreen` (`lib/main.dart`): Manages splash screen, onboarding launch, Android `PROCESS_TEXT` / `SEND` resume checks, sample checks, paste/URL modal, and 3-tab shell (`Home`, `Receipts`, `Settings`). Notice `_executePolicyReview` (`L311+`), `_showCheckAppModal`, and `_showPasteModal` always omit `cloudConsent` (defaulting `false`).
   - `ReviewResultScreen` (`lib/screens/review_result_screen.dart`): Displays hero state, finding cards, permission comparison (`_CleanPermissionListCard`), snapshot sheet, process trace (`AnalysisSavedTraceCard`), Android TTS toggle (`_toggleVoicePlayback`), and opens `WhyThisFindingSheet` (`_openFindingDetails`).
   - `WhyThisFindingSheet` (`lib/widgets/why_this_finding_sheet.dart`): Renders one Evidence Work Card + 3 localized preset chips (`meaning`, `opt_out`, `unknown`) wired to `coordinator.askDeniAboutFinding(...)`. No free-form chat input box exists.
   - `PrivateReadinessSheet` (`lib/widgets/private_readiness_sheet.dart`) & `InstalledAppPickerSheet` (`lib/widgets/installed_app_picker_sheet.dart`): Trigger AICore Nano 4 status/download/warmup and strictly local Android launcher inspection.
   - `CloudConsentSheet` (`lib/widgets/cloud_consent_sheet.dart`): Complete modal sheet showing scrubbed payload preview (`redactedPreview`) and returning `CloudConsentDecision` (`useCloudOnce` / `reviewLocallyInstead` / `cancel`) — **currently unreferenced anywhere in `lib/`**.
   - `OnboardingFlowScreen` (`lib/screens/onboarding_flow_screen.dart`) & `SettingsScreen` (`lib/screens/settings_screen.dart`): Expose 3-tier `ExplanationDepth` (`simple`, `balanced`, `detailed`) and 12 languages (`lib/l10n/enprive_languages.dart`, `.arb` bundles).

2. **Flutter Domain & Validation Layer (`lib/domain/`)**
   - `ReviewCoordinator` (`lib/domain/review/review_coordinator.dart`): Orchestrates policy analysis, PII redaction, streaming progress broadcast (`analysisEvents`), JSON response normalization (`_parseAndValidateBridgeOutput`), offline deterministic regex fallback (`buildDeterministicLocalReceipt`), Android permission attachment (`_attachPermissionComparison`), and 1-turn Deni Q&A (`askDeniAboutFinding`).
   - `EvidenceValidator` (`lib/domain/evidence/evidence_validator.dart`): Normalizes whitespace/quotes, runs exact case-sensitive substring matching (`verifyQuoteAlignment`), assigns `SOURCE_MATCHED` / `INTERPRETATION` / `UNVERIFIED` (`validateFinding`), slices `ContextWindow` (`extractContextWindow`), and computes a 64-bit FNV-1a digest (`computeSnapshotDigest`).
   - `PermissionComparator` (`lib/domain/permissions/permission_comparator.dart`): Matches Android OS requested/granted permissions against policy text tokens deterministically on-device (`PermissionAlignmentState`, `AppPermissionComparisonReport`).
   - `PiiRedactor` (`lib/domain/privacy/pii_redactor.dart`): Applies US/English-centric regex patterns (email, SSN, Student/User IDs, phone numbers, IPv4, street addresses, labeled persons) and defines `comprehensiveCharThreshold = 1400` and `comprehensiveWordThreshold = 220`.

3. **Flutter Local Persistence Layer (`lib/services/storage/receipt_repository.dart`)**
   - `ReceiptRepository`: Local SQLite (`enprive_receipts.db`, `policy_receipts` table) with in-memory test fallback. Persists `PolicyReviewReceipt` JSON including `inferenceSource`, `processSteps`, `thoughtSummary`, `thoughtSignature`, findings, and `permissionReport`.
   - `UserPreferencesRepository`: Local `SharedPreferences` storing `enprive_pref_explanation_depth`, `enprive_pref_language_code`, and `enprive_pref_completed_onboarding`.

4. **Platform Bridge Layer (`lib/services/platform/hybrid_ai_bridge.dart` <-> `android/.../MainActivity.kt`)**
   - Uses `MethodChannel('com.enprive/hybrid_ai')` and an Android-to-Dart streaming callback (`onAnalysisStreamEvent`) for `getDeviceCapability`, `downloadOrCheckModel`, `warmUpModel`, `analyseText`, `getIncomingText`, `listLaunchableApps`, `inspectSelectedApp`, `speakText`, and `stopSpeaking`.

5. **Native Android Layer (`android/app/src/main/kotlin/com/example/enprive/MainActivity.kt`, `android/app/build.gradle.kts`, `AndroidManifest.xml`)**
   - Initializes `FirebaseAppCheck` (`DebugAppCheckProviderFactory` when `FLAG_DEBUGGABLE` is set, else `PlayIntegrityAppCheckProviderFactory`) with `APP_CHECK_DEBUG_TOKEN` injected from `android/local.properties` into `AndroidManifest.xml` placeholders (`L36-37`).
   - Calls `Firebase.ai(backend = GenerativeBackend.googleAI(), useLimitedUseAppCheckTokens = true)`.
   - Handles `ACTION_PROCESS_TEXT` & `ACTION_SEND`, Android 11+ filtered `PackageManager.queryIntentActivities` (`listLaunchableApps`, `inspectSelectedApp`), and local Android `TextToSpeech`.
   - **iOS (`ios/Runner/AppDelegate.swift`)**: Template `FlutterAppDelegate` only; **completely absent** Firebase SDKs and platform channel handlers.

## 4. Current Local / Cloud Inference Flow & Observed Mechanics

1. **Entry Points**: User selects text from Android OS (`ACTION_PROCESS_TEXT`), shares text (`ACTION_SEND`), picks an installed app/benchmark (`InstalledAppPickerSheet`), pastes text/link (`_showPasteModal`), or taps *Why this finding?* (`WhyThisFindingSheet`).
2. **Pre-Inference Check (`ReviewCoordinator.runPolicyReview`)**:
   - Checks `forceLocalManualScan`; if true, runs `buildDeterministicLocalReceipt` (regex keyword rules, marks `InferenceSource.onDevice`).
   - Checks `PiiRedactor.isComprehensivePolicy(policyText)` (`>1,400 chars` or `>220 words`).
     - If `!isComprehensive && !cloudConsent`: invokes `_bridge.analyseText(..., cloudConsent: false, requestedMode: 'ONLY_ON_DEVICE')`.
     - If Nano returns `unavailable`/`error`/`empty` (and `!cloudConsent`), `ReviewCoordinator` (`L231-256`) **does NOT stop**—it executes `PiiRedactor.redact` and immediately calls `_bridge.analyseText(..., cloudConsent: true, requestedMode: 'PREFER_ON_DEVICE')`.
     - If `isComprehensive`: `ReviewCoordinator` skips `ONLY_ON_DEVICE` altogether, scrubs PII, and immediately calls `cloudConsent: true, requestedMode: 'PREFER_ON_DEVICE'`.
3. **Native Kotlin Execution (`MainActivity.kt:analyseText`, `L347-610`)**:
   - Checks `!cloudConsent && requestedMode == "ONLY_IN_CLOUD"` -> returns error `'cloud_consent_required'`.
   - Resolves `InferenceMode`: `!cloudConsent -> ONLY_ON_DEVICE`, `ONLY_IN_CLOUD`, else `PREFER_ON_DEVICE`.
   - Builds `GenerativeModel` via `createModel(includeThoughts = true)` with `"gemini-3.8-flash"`, `OnDeviceConfig`, `responseMimeType = "application/json"`, `temperature = 0.1f`, and `thinkingConfig { includeThoughts = true; thinkingLevel = ThinkingLevel.LOW }` (note: retries once with `includeThoughts = false` if no output arrives before failure, `L559-561`).
   - Streams chunks via `generateContentStream(...)`, emitting incremental `thoughtSummary` and `thoughtSignature` over the Dart platform callback (`onAnalysisStreamEvent`), extracts `response.inferenceSource?.name` (`ON_DEVICE` vs `IN_CLOUD`), and parses JSON via `JSONObject`.
4. **Post-Inference Deterministic Pipeline (`ReviewCoordinator._parseAndValidateBridgeOutput` & `_attachPermissionComparison`)**:
   - Normalizes enum keys (`category`, `severity`, `overall_state`) and runs `EvidenceValidator.verifyQuoteAlignment` on each finding's `quote` against raw `snapshotText` and `redactedSnapshotText`.
   - If model omitted valid findings when `rawState != 'REVIEW_RECOMMENDED'`, clamps to `ReviewOverallState.insufficientEvidence` (or preserves verified findings when present).
   - Calls `PermissionComparator` locally with `AppPermissionSnapshot` (never sent to Gemini).
   - Always attaches calibrated disclaimer (`calibratedDefaultDisclaimer`: *"No concern identified in the reviewed evidence. This is not a safety certification."*) when `noConcern` applies, plus `AppPermissionComparisonReport.calibratedLimitationNotice`.

## 5. Firebase Server Prompt Templates Investigation

Official docs verified: `firebase.google.com/docs/ai-logic/server-prompt-templates`, `firebase.google.com/docs/ai-logic/hybrid-on-device`, `firebase.google.com/docs/ai-logic/monitoring-and-logging`, Isaac Adariku's case study (*Reflection*), and compiled local SDK classes in `firebase-ai-18.2.0-api.jar`.

### Direct Answers to Section 3 Questions (1–10)

1. **Creation & Management**:
   - Authored in **Dotprompt** format (YAML frontmatter `--- ... ---` + Handlebars `{{role "system"}}`, `{{role "user"}}`, `{{var}}`) inside Firebase Console (`AI Services > AI Logic > Prompt templates`) or programmatically via REST API (`firebasevertexai.googleapis.com` endpoints `v1beta.projects.locations.templates` / `v1beta.projects.templates`).
2. **Application References (`Flutter` vs. `Kotlin`)**:
   - **Enprive Android Kotlin (`firebase-ai:18.2.0`)** *already contains*:
     - `Firebase.ai(backend = GenerativeBackend.googleAI(), useLimitedUseAppCheckTokens = true).templateGenerativeModel()`
     - `TemplateGenerativeModel.generateContent(templateId: String, inputs: Map<String, Any?>)`
     - `TemplateGenerativeModel.generateContentStream(templateId: String, inputs: Map<String, Any?>)`
     - `TemplateGenerativeModel.startChat(templateId: String, inputs: Map<String, Any?>, history: List<Content>)` returning `TemplateChat`
   - **Flutter `firebase_ai` (`pub.dev 5.1.0`)**: Exposes Dart `TemplateGenerativeModel` annotated **`@experimental`**. Adopting it in Dart would force adding `firebase_core` + `firebase_ai` + `firebase_app_check` to `pubspec.yaml` and splitting Firebase AI Logic & App Check initialization across Dart and Kotlin.
   - **Comparison with Isaac Adariku's Medium Article (*Reflection*)**: Adariku's Flutter journal app runs **100% cloud inference** via Dart `firebase_ai`, solving multi-platform Play/App Store iteration delays when typos occurred in Dart prompt strings. Enprive differs fundamentally: Enprive executes **hybrid/on-device Gemini Nano 4 via native Kotlin** (absent from `firebase_ai` Dart), queries native Android `PackageManager` & `TextToSpeech`, and enforces `useLimitedUseAppCheckTokens = true` at the single Kotlin `MethodChannel` security boundary. Copying Adariku's Dart `firebase_ai` integration directly would duplicate Firebase clients and fracture consent enforcement. Keeping `TemplateGenerativeModel` inside Enprive's Kotlin AI manager preserves one Firebase/App Check pipeline while gaining server prompt decoupling.
3. **Passing Variables**:
   - Variables are passed as `Map<String, Any?>` matched strictly against `input.schema` in Dotprompt YAML frontmatter. Dotprompt supports `string`, `number`, `integer`, `boolean`, objects, arrays, and optional nullable fields (`?`), validating inputs **before** prompt composition.
4. **Template IDs & Version Organization**:
   - Official constraints: **max 63 characters**, allowed charset **lowercase letters, numbers, and hyphens (`-`)** (dots `.` or underscores `_` must be avoided in template IDs).
   - Best practice: immutable versioned IDs (`enprive-finding-explanation-cloud-v1-0-0`, `...-v1-1-0`) rather than mutating one mutable ID in place, allowing zero-downtime Remote Config pointer switching and safe multi-version client compatibility.
5. **Model Settings & Generation Config**:
   - Controlled inside Dotprompt YAML frontmatter: `model: 'gemini-3.8-flash'` (or `'gemini-2.5-flash'`), `config:` (`temperature`, `topP`, `maxOutputTokens`), and thinking config (`thinkingLevel` OR `thinkingBudget` — **verified rule**: setting both throws an error, and Gemini 4.x rejects `thinkingBudget` with HTTP `400`).
6. **Structured Response Enforcement**:
   - Controlled via `config: { format: json, outputSchema: ... }` using OpenAPI-compatible schema syntax (`string`, `integer`, `(array)`, `(object)`, optional `?`).
   - **Critical Limitation Confirmed in Official Docs**: **Constraining outputs to an enum list is NOT currently supported in Server Prompt Templates** (nor are full JSON Schema spec blocks outside OpenAPI frontmatter syntax). Therefore, fields like `overall_state`, `category`, and `severity` **cannot** rely on server-side enum enforcement and still require deterministic client normalization in `ReviewCoordinator`.
7. **When a Template Cannot Be Retrieved / Execution Fails**:
   - Invalid/deleted template IDs, missing input schema variables, or offline states raise exceptions/HTTP errors (`400`/`403`/`404`/network errors). **Preview Status Warning**: Server Prompt Templates are in **Public Preview** with no SLA or deprecation guarantee. Enprive must handle template failures explicitly by displaying an actionable error with manual/local inspection options—**never silently falling back to unconsented routes or hiding failure**.
8. **Independent Testing Outside the App**:
   - Templates can be tested directly in Firebase Console's interactive prompt runner, automated via `firebasevertexai.googleapis.com` REST API (`projects.locations.templates` integration suite in CI against a staging project), and linted locally with Genkit/Dotprompt YAML schema parsers before locking or updating Remote Config.
9. **Deployment & Rollback**:
   - Create `...-v1-1-0` -> run staging eval suite -> **Lock template** in Firebase Console -> update Remote Config parameter -> rollback simply repoints Remote Config back to locked `...-v1-0-0` (zero app binary release). Never edit an already-referenced unlocked template in production.
10. **Security, IAM Permissions & the "Template-Only Mode" Trap**:
    - Management requires `roles/firebasevertexai.admin` (`firebasevertexai.configs.update`) or `roles/firebase.admin`; lock status prevents accidental console edits but authorized IAM users can unlock templates.
    - **CRITICAL COMPATIBILITY TRAP**: Firebase Console offers a project-wide **"Enforce template-only mode"** setting that rejects all non-template Gemini requests with **`403 Unauthorized`**. Because Enprive's `GenerativeModel` hybrid mode (`PREFER_ON_DEVICE` cloud fallback, `ONLY_IN_CLOUD` fallback, and any future `LiveGenerativeModel` call) hits standard `generateContent` endpoints rather than `templateGenerateContent`, **enabling Template-Only mode globally would break hybrid inference fallbacks in production!** Template-Only mode must **NOT** be enabled unless 100% of cloud `GenerativeModel` calls are retired or moved to a separate Firebase project.

### Operational Lifecycle, Caching, Resilience & Validation

- **SDK Selection (Privacy Advantage)**: Add `com.google.firebase:firebase-config` (via `firebase-bom`) in Android Kotlin **without** `firebase-analytics`. Global defaults, caching, fetch/activate, and app-version conditions work cleanly without adding Analytics SDK tracking.
- **When Configuration Is Fetched**: Perform an asynchronous, non-blocking `fetch()` at app startup (after first frame so splash screen / offline startup never stalls) and optionally on foreground resume if cache age exceeds interval.
- **Caching & Avoiding Excessive Requests**: Firebase Remote Config caches values persistently on-device. Keep the **12-hour default `minimumFetchIntervalInSeconds = 43200`** in release builds (setting `0` only under debug builds for testing) so repeated checks never hammer Firebase endpoints. Avoid per-review `fetch()` calls.
- **Defaults (`setDefaultsAsync`)**: Embed compile-time defaults in `android/app/src/main/res/xml/remote_config_defaults.xml` so offline launches, fresh installs offline, or blocked networks resolve deterministic known-good IDs/flags immediately.
- **Safe Activation Timing (No Mid-Review Swaps)**: Prefer `fetch()` asynchronously -> `activate()` **at cold start / session boundary** rather than calling `fetchAndActivate()` or `addOnConfigUpdateListener` auto-activation inside an active review or Deni conversation. This guarantees an Evidence Receipt and its follow-up findings use a consistent template configuration.
- **If Firebase Is Unavailable**: `getDeviceCapability`, `ONLY_ON_DEVICE` Gemini Nano 4 inference, `buildDeterministicLocalReceipt`, `PermissionComparator`, `ReceiptRepository`, and local `TextToSpeech` continue operating **100% offline** using cached or XML default Remote Config values.
- **Preventing Invalid Template IDs From Breaking the App**:
  1. Enforce a strict Kotlin allowlist regex on every fetched template ID: `^enprive-[a-z0-9-]+-v\d+-\d+-\d+$` (`length <= 63`).
  2. Reject malformed, empty, or unexpected template IDs before invoking `TemplateGenerativeModel`, logging a local warning (no payload) and falling back to safe compile-time defaults or explicit local/manual retry UI.
  3. Catch runtime `TemplateGenerativeModel` HTTP `400`/`403`/`404` exceptions cleanly—never silently re-route between consent boundaries.
- **Rollback**: Use Firebase Console **Remote Config > Change History > Roll back** (creates a new version pointing back to the previously locked template ID such as `...-v1-0-0`).
- **Security Invariant**: Remote Config values are readable by any device running the app (and count against the project quota of 3,000 parameters / 1,000,000 total characters / 300 saved template versions). Never store API keys, tokens, secrets, PII, or user consent/authorization overrides inside Remote Config.

## 7. Privacy, Security & Operational Risk Findings

1. **CRITICAL — Silent Cloud Escalation Bug (`ReviewCoordinator.kt`/`dart`)**: Must be resolved *before* introducing any cloud templates. `ReviewCoordinator.runPolicyReview` (`L232-256`) and `askDeniAboutFinding` (`L441-465`) currently bypass `CloudConsentSheet` completely and pass `cloudConsent: true`. Any future template wired behind `ReviewCoordinator` would receive unconsented policy text unless `CloudConsentSheet` and `ReviewExecutionResult.requiresConsentChoice` are restored as blocking gates.
2. **CRITICAL — Google Cloud Prompt/Response Logging by Default**: Official Firebase AI Logic AI Monitoring docs confirm that enabled monitoring captures **raw prompt text and model responses** in Google Cloud Logging & Trace by default. Because Enprive processes privacy policies selected by parents/teachers (potentially referencing student/child apps or accidentally highlighted emails/names not caught by English-only `PiiRedactor` regexes), Enprive must **add a Cloud Logging exclusion filter** on the `_Default` sink (`resource.type="firebasevertexai.googleapis.com/Client"`) or keep AI Monitoring trace payload capture disabled, retaining only count/latency/token/status aggregates.
3. **App Check Verification (`MainActivity.kt:65-72, 114, 392`)**:
   - Currently sound in code: `useLimitedUseAppCheckTokens = true` enforces replay protection on both `createOnDeviceModel()` and `createModel()`, while `FLAG_DEBUGGABLE` selects `DebugAppCheckProviderFactory` vs. `PlayIntegrityAppCheckProviderFactory`, and `APP_CHECK_DEBUG_TOKEN` stays outside VCS via `android/local.properties`.
   - Operational checklist items remaining before release: verify Play Integrity SHA-256 fingerprints in Firebase Console and audit AI Logic rate quotas (`RPM`, `RPD`, `TPM`, `TPD`) so `429 Quota Exceeded` responses trigger calm localized retry/local-fallback UX rather than raw errors.
4. **PII Redaction Coverage (`PiiRedactor`)**: Regex rules work cleanly for English patterns (`emails`, `phones`, `SSN`, `Student/User ID`, `IPv4`, `Street/Ave`, `Parent/Child/Student: Name`), validated in `pii_redactor_test.dart`, **but do not catch unstructured names or non-English address/ID formats across the other 11 supported languages**. Explicit user disclosure & preview (`CloudConsentSheet`) remains mandatory before any text crosses to cloud templates.
5. **Input Validation & Prompt Injection**: Currently, Kotlin concatenates `$systemPrompt\n\n--- POLICY TEXT ---\n$text` inside one prompt string. Adopting Dotprompt `{{role "system"}}` / `{{role "user"}}` separation + explicit `<untrusted_policy_snapshot>` delimiters + Dotprompt `input.schema` character bounds reduces injection surface, while `EvidenceValidator` remains the non-bypassable deterministic filter.
6. **Non-Sensitive Operational Telemetry Gap**: `PolicyReviewReceipt` stores `inferenceSource`, `processSteps`, `thoughtSummary`, and `thoughtSignature`, **but omits `promptId`, `promptVersion`, `modelVersion`, `latencyMs`, `UsageMetadata` token counts, and `validationOutcome`**. Extending receipts locally with these metadata fields supports repeatable evaluation without logging policy text or package lists.
